# Artifacts

Derived view. One row per artifact file. Regenerate rather than edit.

An artifact settles one question, and it is filled by whoever owns it. A
`demonstrator` prototype brief is filled by `/fde:prototype`.

Artifacts are written by hand against a milestone. The shapes they take are
in [`../../setup/artifact-templates.md`](../../setup/artifact-templates.md).

A build spec, an implementation plan and an execution record belong to one
session's work rather than to the engagement as a whole. So they live with
that session in the `my-sessions` folder instead of here. This folder holds
only the standing documents that outlive a session: briefs, specs and
catalogues a milestone reads.

A stub states what the artifact must answer and who can answer it. Filling
it is later work by whoever owns it.

No backlinks. An artifact never lists what needs it. Reverse lookup is
`grep -rl <artifact-slug> project/`.
