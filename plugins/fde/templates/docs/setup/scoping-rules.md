# Scoping rules

Purpose: this engagement's corrections to how the scoping skills run. One
section per skill; each skill reads only its own.
Done when: never. Rules accrete from corrections you give during a run.

The skill bodies are generic mechanism and the template owns them. This
file is the client's judgement, and rules here override the skills' general
steps.

Each rule is dated with its provenance. Amend in place rather than
deleting; the original reading stays visible.

There is no version key here. Scoping output is written once and revised in
place rather than cached. So a new rule reaches the work the next time the
relevant skill runs, with no invalidation step.

## The interview discipline

Read on every run. A rule below overrides these only where it says so
explicitly.

1. Read state before asking. Parse the target artefact and classify every
   row as filled, open or diverged. A filled row is never re-asked unless
   the user asks for it.
2. One question at a time. Use multiple choice wherever the answer space
   is closed: authority tier, the five mechanism letters, a role already
   named elsewhere in the engagement.
3. Tier every captured fact. An answer traced to something in `raw/` takes
   that source's tier from its `raw/ledger.md` row: `statutory`,
   `artefact`, `stated` or `ours`. It cites the file and page. Tier is
   assigned once, at intake, and travels; nothing here reassigns it. For an
   answer with no artefact behind it, ask who it came from. The client said
   it, which is `stated`, or it is the FDC's read, which is `ours`.
   Guardrail 7.
4. Never guess. An "I don't know" leaves the row open and writes a row
   into `project/open-questions.md` naming who can answer it. Guardrail 3.
   A plausible answer invented here is worse than a blank row, because it
   will be read later as something the client said.
5. Write after every answer, not at the end, so an interrupted session
   loses nothing and re-running resumes.
6. Report on exit: what was filled, what is still open, what questions
   were raised, and which command comes next.
